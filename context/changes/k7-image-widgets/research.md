# Research — k7-image-widgets

## Recall (before exploring)

`recall_context` on the goal surfaced the settled decision that motivated this
change — `[node:e24b75ab]` "comic-of-the-day pulls an external image from RSS and
therefore carries attribution, keyword filtering and copyright exposure, while
ascii-art-of-the-day is generated by the AI ... carries none of that" — plus the
weather/freshness precedent `[node:8f453152]` and `[node:822d1381]` ("every
upstream answer carries its own age... the honest field is made impossible to
omit"), the Kilo Gateway addressing/cost-logging decision `[node:279d73e0]`, the
secrets-server-side-only constraint `[node:ac006a24]`, the shared Card shell
decision `[node:240ae1c0]`, and the full token/typography/contrast/Safari-15
constraint set. No domain entities exist yet for either widget — `domain_model()`
confirms Weather itself isn't modelled as an entity either, so this follows the
established precedent of not minting entities for simple upstream-backed cards.

Recall did **not** answer: the exact current shape of the weather widget's code,
the verbatim schema field lists, whether the `aiCalls.purpose` enum already has
`'ascii-art'`, whether an `upstream_cache` `Upstream` enum value exists for RSS,
whether a Kilo Gateway client already exists (from the sibling Faza 4 branch, per
the task instructions), and what RSS parsing library (if any) is installed. That
was the exploration agenda.

## Findings (file:line)

**Weather precedent to imitate:**
- `src/client/lib/K7Weather.svelte` — `customElement={{ tag: 'k7-weather', props: {...} }}` (L10), wraps `<Card>` (L76) with `state` derived from `failed`/`aged.stale` (L41-43), `$effect`-driven poll loop with `AbortController` + `setInterval` (L60-69), keeps stale data on screen rather than clearing it on fetch failure (L46-58), staleness banner styled via `var(--warn)` (L94-97, L136). Polish copy is lowercase/terse, diacritics dropped in some labels (`wilgotnosc`), bracket-glyph warnings (`[!] dane sprzed …`).
- **No per-card `.stories.ts` precedent exists** — only `K7Card.stories.ts` (the shared shell) has a story. We are the first to add a per-widget story.
- `src/server/upstream/open-meteo.ts` — free-function shape: `weatherUrl`, `weatherCacheKey` (all cache-relevant params folded into the key, L82-84), `fetchWeather`. No shared `UpstreamClient` interface — each upstream module is just functions called from the route handler.
- `src/server/upstream/freshness.ts` — `createFreshnessService(cache): (options: FetchThroughOptions<T>) => Promise<Aged<T>>`, `fetchWithTimeout(url, timeoutMs=8000)`. Serves cached copy under `freshForSeconds`; on miss/expiry calls `fetcher()` and stores via `cache.put`; on fetcher throw, falls back to stale cache (`stale:true`, `onFallback` called) or rethrows if nothing cached. **Reused as-is for both new cards.**
- `src/server/index.ts:38` builds `fetchThrough` once at boot; `/api/weather` route (L160-193) is the pattern: validate query params → 400, `fetchThrough` in try/catch → JSON `Aged<T>` on success, `503 {error,detail}` on total failure, `onFallback` logs via `req.log.warn` (not Sentry — expected outage, not an error).
- `src/server/ports/repositories.ts:54-57` `UpstreamCacheRepository { get(key), put(key, upstream, payload, fetchedAt?) }`, already wired in `src/server/adapters/drizzle/index.ts:189-203`. **No new repository needed** — just new `Upstream` enum values and cache keys.

**Schema (verbatim field lists) — `docs/handoff/layout.schema.yaml`:**
- `params.comicOfTheDay` (L329-368), required `[rssUrl]`: `rssUrl`, `itemSelector?`, `filterKeywords?: string[]`, `cacheDurationHours` (default 24), `maxWidthPx` (default 380), `linkToSource` (default true), `creditText?`, `fallbackImageUrl?`.
- `params.asciiArtOfTheDay` (L370-406), required `[prompt]`: `prompt`, `model` (default `"kilo-auto/free"`), `cacheDurationHours` (default 24), `maxWidthChars` (default 60), `maxHeightLines` (default 24), `colorized` (default true), `seed?`, `fallbackArt?`.
- `layout.yaml` already declares both cards (`id: komiks` L73-77, `id: ascii` L99-104) with placeholder values (`rssUrl: "https://example.invalid/feed.xml"`).

**aiCalls / upstream_cache — `src/server/db/schema.ts`:**
- `aiCalls.purpose` enum (L94) **already includes `'ascii-art'`** — no migration needed there.
- `upstreamCache.upstream` enum (L120) is `'open-meteo' | 'google-calendar' | 'kilo-gateway'` — **no RSS value**. Captured as a constraint (`[node:e38c12d4]`): needs a new enum member (e.g. `'rss'`) in both `schema.ts` and `domain/types.ts:65`, plus a Drizzle migration.

**Kilo Gateway client — does not exist.** `grep -rniE "kilo|gateway"` hits only `config.ts` (key threading + redaction), the unused `'kilo-gateway'` enum member, and the mocked-up `K7Card.stories.ts` example. Faza 4 (chat) has not landed in this worktree — no `ConversationService`, no chat route, nothing under a `chat/`/`conversation/` dir. Captured as an issue (`[node:6a05648a]`): build a minimal standalone client, following `open-meteo.ts`'s shape, threading `config.kiloGatewayKey` in as a parameter.

**RSS/Atom parsing — absent.** `package.json` has no `rss-parser`/`fast-xml-parser`/`xml2js`. Captured as an issue (`[node:1dd47195]`): needs a new dependency.

**Test conventions** — `test/freshness.test.ts`: `node:test` (`describe`/`it`/`beforeEach`), `node:assert/strict`, in-memory DB per test, injected fixed clock (`now: () => T0`), plain `assert.equal`/`assert.rejects` with descriptive messages. Run via `node --test test/*.test.ts`.

**`.env.schema`** — `KILO_GATEWAY_KEY` already declared, `@sensitive @required`. No new secret needed for either widget (`rssUrl` is a layout param, not a secret).

**`npm run check`** — `lint && lint:tokens && test && build`; `build` = `typecheck (tsc + svelte-check) && vite build && build-precache`. This is the full gate before PR.
